# APP-008.3-R5-C1 — Hotelbeds Availability Response Envelope and No-Availability Handling

**Document ID:** APP-008.3-R5-C1  
**Status:** Draft — Revised for Architect Review  
**Capability:** Accommodation Availability  
**Provider:** Hotelbeds  
**Iteration:** R5-C1  
**Depends On:** APP-008.3-R1 through R4-C1  
**Scope:** Hotelbeds Availability response mapping

---

## 1. Purpose

APP-008.3-R5-C1 corrects the Hotelbeds Availability response mapping boundary to support the two verified supplier response variants established during controlled testing.

The first verified response variant represents availability and has the structure:

    response.hotels.hotels[]

The second verified response variant represents valid no availability and has the structure:

    response.hotels.total === 0

The current R5 mapper supports the first variant but incorrectly rejects the second variant with:

    Malformed Hotelbeds availability response: hotels collection missing.

The purpose of this revision is to ensure that both verified Hotelbeds response variants are correctly mapped into the existing canonical Availability result.

No changes are required to R2, R3, R4-C1, R6, R7, or R8.

## 3. Confirmed Root Cause

The current mapper assumes that an object containing `response.hotels` must also contain a hotel collection.

The verified no-availability response disproves that assumption.

The current mapper therefore incorrectly transforms this valid response:

    {
      "hotels": {
        "total": 0
      }
    }

into:

    Malformed Hotelbeds availability response: hotels collection missing.

The correction belongs exclusively to R5.

## 6. Supported Hotelbeds Response Variants

### 6.1 Availability Present

When:

    response.hotels.hotels

is an array, the mapper must use that array as the Hotelbeds hotel collection.

Example:

    {
      "hotels": {
        "hotels": [
          {
            "code": 26996,
            "rooms": []
          }
        ],
        "checkIn": "2026-09-15",
        "total": 1,
        "checkOut": "2026-09-18"
      }
    }

The existing hotel, room, and rate mapping behaviour must remain unchanged.

---

### 6.2 Valid No Availability

When:

    response.hotels

is an object and:

    response.hotels.total === 0

the mapper must recognize the response as a valid no-availability response.

It must not throw:

    Malformed Hotelbeds availability response: hotels collection missing.

Instead, it must produce the existing canonical no-availability result used by the application.

The implementation must use the existing canonical result semantics rather than introducing a new result type or status.

---

## 7. Response Classification Order

The mapper should classify the response in a deterministic order.

Recommended logic:

1. Recognize an array response if that is an existing supported application form.
2. Recognize `response.hotels.hotels[]` as the Hotelbeds hotel collection.
3. Recognize `response.hotels.total === 0` as valid no availability.
4. Preserve existing intentionally supported response forms.
5. Reject genuinely malformed responses.

The exact implementation structure remains an implementation detail, provided behaviour and scope are preserved.

---

## 8. No-Availability Semantics

The response:

    {
      "hotels": {
        "total": 0
      }
    }

must map to the application's existing canonical no-availability semantics.

The mapper must not fabricate:

- hotels;
- rooms;
- rates;
- prices;
- availability;
- supplier data.

The result should represent that the request was successfully processed but no availability was returned.

No supplier error should be raised solely because the hotel collection is absent when:

    response.hotels.total === 0

---

## 9. Malformed Response Handling

The mapper must continue to fail closed for responses that do not match a supported Hotelbeds response structure.

Examples of genuinely malformed or unsupported content include responses where:

- `hotels` is absent;
- `hotels` is neither an object nor an existing supported representation;
- `hotels.total` is not zero;
- `hotels.hotels` is absent when the response does not qualify as a valid no-availability response;
- the response contains an unsupported structure that cannot safely be interpreted.

Do not treat an arbitrary missing collection as no availability.

Only the verified Hotelbeds condition:

    response.hotels.total === 0

establishes the no-availability interpretation.
