Implement APP-008.3-R1 — Availability Foundation for GCT Core.

This is the first implementation iteration of APP-008.3 — Accommodation Availability and Hotelbeds Availability Integration.

Source Market

Add explicit sourceMarket support.

Occupancy Model

The existing scalar rooms: number is insufficient as the canonical Availability occupancy representation.

Introduce a canonical occupancy-group structure capable of representing:

rooms
adults
children
childAges

Conceptually:

occupancies:
[
  {
    rooms: 1,
    adults: 2,
    children: 0,
    childAges: []
  }
]

and:

occupancies:
[
  {
    rooms: 1,
    adults: 2,
    children: 1,
    childAges: [7]
  }
]

The model SHALL support multiple occupancy groups with different room, adult, child and child-age requirements.

Do not collapse groups into aggregate totals.

Occupancy Semantics

rooms: number of rooms represented by the occupancy group.

adults: number of adults per room represented by the group.

children: number of children per room represented by the group.

childAges: ages of children represented by the group.

The relationship between children and childAges MUST be preserved.

Occupancy Validation

Implement canonical validation.

rooms MUST be a positive integer.

Reject at minimum:

0
-1
1.5
NaN
Infinity

adults MUST be a positive integer unless an existing canonical rule explicitly permits zero adults.

children MUST be a non-negative integer.

If children = 0, childAges MUST be empty.

If children > 0, then:

childAges.length === children

MUST hold.

A child count without corresponding ages is invalid.

Too many or too few ages is invalid.

Child Age Validation

Child ages MUST:

be integers;

be non-negative;

have the same count as children.

Do not introduce a Hotelbeds-specific maximum child age in R1 unless it already exists canonically.

Multiple Occupancy Groups

The canonical model SHALL support:

occupancies: OccupancyGroup[]

Each group may have different room, adult, child and child-age values.

Do not flatten groups into total rooms/adults/children.

Existing API Compatibility

Determine whether the canonical model can be extended while preserving callers.
