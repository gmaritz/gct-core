# Objective

Implement the canonical Journey Validation Pipeline.

The pipeline validates journey composition requests before orchestration and validates the resulting Journey Aggregate before it is returned.

Validation shall be separated into distinct responsibilities rather than implemented as a single validator.

---

# Architectural Principles

Validation is a business capability.

Each validator has one responsibility.

Validators remain stateless.

Validators remain supplier-independent.

Validators never perform orchestration.

Validators never retrieve provider data.

# JourneyQueryValidator

Purpose

Validate incoming requests.

Responsibilities

- request exists
- context exists
- journey type valid
- strategy valid
- traveller requirements valid
- stay requirements valid

No business composition rules.

---

# JourneyCompositionValidator

Purpose

Validate composition feasibility.

Responsibilities

Examples

- destination supplied
- accommodation permitted
- duration compatible
- journey type supported
- required business capabilities available

This validator evaluates business rules.

It does not call providers.

---

# JourneyAggregateValidator

Purpose

Validate the completed Journey Aggregate.

Responsibilities

Examples

- identity exists
- classification exists
- duration valid
- destinations exist
- traveller rules valid
- aggregate internally consistent

# Validation Philosophy

Validation remains structural.

Validators shall never

- retrieve accommodation
- retrieve rates
- calculate pricing
- create bookings
- call providers

Validation precedes orchestration.

---

# Pipeline Behaviour

The pipeline shall

- execute validators sequentially
- stop on first failure
- return immutable validation result
- expose no provider behaviour

# Milestone Outcome

Upon successful completion, GCT Core shall expose a canonical Journey Validation Pipeline that validates journey requests and Journey Aggregates through a sequence of focused, stateless validators.

The pipeline establishes a reusable validation architecture for all future journey-related capabilities while maintaining complete separation from orchestration, supplier integrations, pricing and reservations. It provides the quality gate that ensures only valid journeys progress into the Journey Composition Engine.
