# Objective

Implement the canonical Reservation Service.

The Reservation Service is the orchestration layer of the Reservation Capability.

It coordinates validation, policy evaluation and aggregate construction.

The Reservation Service shall contain no business rules.

# Reservation Service Context

Create

```typescript
ReservationServiceContext
```

Purpose

Provide a single immutable orchestration context throughout the reservation lifecycle.

Contains

- reservationRequest
- validationResult
- policyResult
- builderResult
- reservation
- metadata

The context is created once and enriched by each orchestration stage.

---

# Reservation Service

Create

```typescript
ReservationService
```

Responsibilities

- create ReservationServiceContext
- invoke ReservationValidationPipeline
- invoke ReservationPolicyPipeline
- invoke ReservationBuilder
- return ReservationResult

The service shall never

- perform validation
- evaluate policies
- construct aggregates
- communicate with providers
- persist reservations

---

# Dependency Injection

Inject

- ReservationValidationPipeline
- ReservationPolicyPipeline
- ReservationBuilder

The service shall not instantiate collaborators directly.

---

# Orchestration Rules

The service shall

1. Create immutable ReservationServiceContext.
2. Execute ReservationValidationPipeline.
3. Stop immediately if validation fails.
4. Execute ReservationPolicyPipeline.
5. Stop immediately if policy denies reservation.
6. Execute ReservationBuilder.
7. Return immutable ReservationResult.

The service coordinates only.

---

# Reservation Result

The Reservation Service returns the canonical ReservationResult defined by APP-001D.

No presentation models or view models shall be returned.

---

# Failure Behaviour

Business failures shall return ReservationResult.

Unexpected technical failures may raise exceptions.

Validation and policy failures shall never throw exceptions.
