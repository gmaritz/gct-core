# Objective

Implement the canonical Reservation Snapshot Model Library.

The library defines immutable commercial records that preserve the state of a reservation at specific points in time.

Snapshot models are historical records.

They are not live business aggregates.

# Snapshot Contract

Create

```typescript
ReservationSnapshot
```

Every snapshot shall implement this contract.

Minimum properties

```typescript
snapshotId

capturedAt

version
```

All properties are immutable.

---

# Journey Snapshot

Represents the booked journey exactly as sold.

Typical properties

- journey identifier
- title
- destination
- duration
- accommodation summary
- experience summary

This snapshot shall never reference the live Journey aggregate.

---

# Traveller Snapshot

Represents a traveller at the time of booking.

Typical properties

- traveller identifier
- full name
- contact details
- nationality
- traveller type

Remain immutable.

---

# Accommodation Snapshot

Represents booked accommodation.

Typical properties

- accommodation identifier
- property name
- room type
- meal basis
- check-in
- check-out

Remain immutable.

---

# Pricing Snapshot

Represents the commercial pricing agreed with the customer.

Typical properties

- currency
- total price
- taxes
- discounts
- fees

No live pricing calculations.

---

# Payment Snapshot

Represents payment state.

Typical properties

- payment status
- payment method
- amount received
- balance outstanding

No payment processing logic.

---

# Supplier Reference

Represents supplier-side reservation references.

Typical properties

- provider identifier
- supplier booking reference
- confirmation number

Remain immutable.

---

# Reservation Timeline

Represents the chronological history of the reservation.

Typical milestones

- Created
- Quoted
- Pending
- Confirmed
- Amended
- Cancelled
- Completed

Timeline behaviour will be introduced later.

---

# Reservation Metadata

Represents immutable technical metadata.

Typical properties

- createdAt
- updatedAt
- version

No business behaviour.

---

# Versioning

Every snapshot shall support versioning.

Future reservation amendments shall create new snapshots without modifying historical records.

# Milestone Outcome

Upon successful completion, GCT Core shall expose a canonical Reservation Snapshot Model Library providing immutable, versionable commercial records for journeys, travellers, accommodation, pricing, payments and supplier references.

The library establishes the foundation for preserving historical booking integrity while remaining independent of live business aggregates and future domain evolution.
