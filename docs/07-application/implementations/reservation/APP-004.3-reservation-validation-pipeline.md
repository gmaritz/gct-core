# Objective

Implement the canonical Reservation Validation Pipeline.

The pipeline validates reservation requests, reservation snapshots and commercial integrity before any Reservation Builder or Reservation Service executes.

The pipeline coordinates validation.

It does not contain validation rules.

# Validation Architecture

The Reservation Validation Pipeline coordinates three specialised validators.

```text
Reservation Request

        │

        ▼

Reservation Query Validator

        │

        ▼

Reservation Snapshot Validator

        │

        ▼

Commercial Integrity Validator

        │

        ▼

Reservation Validation Result
```

Each validator has a single responsibility.

---

# Reservation Query Validator

Responsibilities

- validate mandatory request fields
- validate traveller information
- validate reservation dates
- validate request structure

The validator shall not inspect commercial snapshots.

---

# Reservation Snapshot Validator

Responsibilities

- validate JourneySnapshot
- validate TravellerSnapshots
- validate AccommodationSnapshots
- validate PricingSnapshot
- validate PaymentSnapshot

The validator shall ensure snapshot completeness and structural consistency.

---

# Commercial Integrity Validator

Responsibilities

- validate reservation coherence
- validate traveller/pricing consistency
- validate payment/reservation status compatibility
- validate supplier references where applicable

The validator evaluates commercial integrity only.

---

# Reservation Validation Pipeline

Responsibilities

- coordinate validator execution
- aggregate validation output
- terminate when required
- return immutable ReservationValidationResult

The pipeline shall not implement validation rules directly.

---

Immutable.

---

# Commercial Integrity Findings

Commercial integrity findings represent business observations.

Examples

- inconsistent pricing
- missing supplier reference
- incomplete accommodation snapshot
- traveller mismatch

Integrity findings are distinct from validation errors.

---

# Dependency Injection

Inject

- ReservationQueryValidator
- ReservationSnapshotValidator
- CommercialIntegrityValidator

The pipeline shall not instantiate collaborators directly.

---

# Failure Behaviour

Validation failures shall produce ReservationValidationResult.

Unexpected technical failures may raise exceptions.

Business validation failures shall never throw exceptions.

# Future Evolution

Future milestones may extend the validation pipeline with:

- fraud detection

- travel document validation
- payment risk assessment

---

# Milestone Outcome

Upon successful completion, GCT Core shall expose a canonical Reservation Validation Pipeline that coordinates request validation, snapshot validation and commercial integrity validation through specialised validators.

The pipeline establishes the first transactional validation framework within GCT Core, ensuring that every reservation entering the Reservation Capability is structurally valid, commercially coherent and ready for construction by the Reservation Builder while maintaining strict separation of concerns.
