# Objective

Implement the Hotelbeds Mapping Library.

The mapping library translates Hotelbeds Provider Models into Canonical Accommodation Models.

Mappings shall be explicit, deterministic and one-directional.

The mapping library shall contain no business orchestration.

---

# Architectural Principle

Provider Models belong to Hotelbeds.

Canonical Models belong to GCT Core.

The Mapping Library is the only layer permitted to translate between them.

No other layer shall perform provider-to-canonical mappings.

---

# Mapping Philosophy

Each mapper has one responsibility.

No mapper shall perform unrelated transformations.

Complex mappings shall compose smaller mappers.

---

# Aggregate Mapper

Create

```typescript
HotelMapper
```

Responsibilities

- Coordinate mapping.
- Compose specialised mappers.
- Produce a Canonical Accommodation aggregate.

The HotelMapper shall not implement mapping logic directly.

It delegates to specialised mappers.

# Milestone Outcome

Upon successful completion, GCT Core shall contain a modular Hotelbeds Mapping Library that converts Hotelbeds Provider Models into Canonical Accommodation Models using small, focused, stateless mappers.

The Mapping Library becomes the only translation layer between external supplier models and internal application models, preserving complete separation between provider implementations and business concepts.
