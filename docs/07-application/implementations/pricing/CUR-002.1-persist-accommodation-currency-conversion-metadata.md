# Copilot Implementation — CUR-002.1: Persist Accommodation Currency Conversion Metadata

## Objective

Persist the CUR-002 currency conversion details in the canonical Reservation accommodation snapshots, using the existing JSON persistence structure.

The implementation must ensure that conversion information survives reservation creation, persistence, database retrieval and domain reconstruction.

## Mandatory development workflow

Follow `docs/09-governance/GOV-DEV-001-DEVELOPMENT-PROCESS.md` as the single source of truth for the development workflow.

## Approved design

Extend the existing `AccommodationSnapshot` with an optional, typed currency conversion object.

The object must retain:

- `fromCurrency`
- `toCurrency`
- `exchangeRate`
- `convertedAmount`
- `policyId`

The existing fields remain authoritative:

- `packageStopId` identifies the accommodation stop.
- `supplierPrice.amount` retains the original supplier amount.
- `supplierPrice.currency` retains the original supplier currency.

Do not overwrite or replace the original supplier price.

The existing `PricingSnapshot` continues to hold the authoritative final ZAR package total.

## Implementation scope

Inspect and update only the necessary parts of:

1. Canonical accommodation snapshot type.
2. Reservation aggregate snapshot freezing logic in `reservation.ts`.
3. Customer journey reservation construction in `customer-journey-reservation-service.ts`.
4. Prisma repository serialization and reconstruction in `canonical-reservation-prisma.repository.ts`.
5. Relevant tests.

Ensure the conversion metadata is populated from the actual priced accommodation line item, not independently recalculated using a different rate or policy.

For ZAR accommodation without conversion, the conversion object should remain absent.

For EUR accommodation converted to ZAR, persist the exact rate, converted amount and policy used for the quote.

## Tests required

Add focused tests proving:

1. EUR supplier price remains unchanged.
2. Conversion metadata is attached to the correct accommodation stop.
3. Different accommodation stops retain their own conversion details.
4. Aggregate snapshot freezing preserves the conversion object.
5. Prisma save-and-restore round-trip preserves all conversion fields.
6. Existing reservations without conversion metadata remain compatible.
7. ZAR-only accommodation does not acquire unnecessary conversion metadata.

## Constraints

- No Prisma schema changes.
- No database migration.
- No changes to CUR-002 conversion calculations or rounding.
- No changes to Hotelbeds integration.
- No frontend changes.
- No unrelated refactoring.
- Preserve all existing uncommitted work, including the Step 1 fix and CUR-002 implementation.
- Do not stage, commit or push.
