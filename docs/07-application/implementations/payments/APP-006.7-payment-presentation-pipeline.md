# Objective

Implement the canonical Payment Presentation Pipeline.

The Presentation Pipeline transforms immutable Payment Engine results into presentation models and UI-ready view models.

The pipeline performs presentation mapping only.

It contains no business logic, payment processing, validation, or provider communication.

---

- Barrel exports

# Presentation Models

## PaymentSummaryPresentationModel

Commercial payment summary.

Contains:

- payment reference
- reservation reference
- traveller
- total amount
- currency
- payment method
- payment status

Immutable.

---

## PaymentLifecyclePresentationModel

Represents the payment lifecycle.

Contains:

- authorization status
- capture status
- settlement status
- refund status
- lifecycle timeline

Immutable.

---

## PaymentStatusPresentationModel

Represents customer-facing payment state.

Contains:

- headline
- status badge
- next action
- warnings
- informational messages

Immutable.

---

## PaymentViewModel

UI-ready model.

Contains:

- summary
- lifecycle
- status
- CTA metadata
- badge styles
- display labels

Immutable.

---

# PaymentPresentationMapper

Responsibilities:

- map successful PaymentEngineResult
- create presentation models
- normalize optional values
- apply immutable defaults

Returns:

```typescript
PaymentSummaryPresentationModel

PaymentLifecyclePresentationModel

PaymentStatusPresentationModel
```

Returns:

```typescript
null
```

when payment processing was unsuccessful.

---

# PaymentViewModelProvider

Responsibilities:

- map presentation models
- apply UI defaults
- normalize labels
- normalize badge styles
- normalize CTA metadata

Returns:

```typescript
PaymentViewModel
```

The provider remains stateless.

---

# Presentation Rules

The Presentation Pipeline:

- never performs business logic
- never evaluates payment policies
- never invokes providers
- never mutates engine results
- never formats provider-specific values

Presentation only.

---

# Constructor Injection

The View Model Provider receives:

- PaymentPresentationMapper

through constructor injection.

No component creates another component internally.

# Milestone Outcome

Upon successful completion, GCT Core shall expose a deterministic, provider-independent Payment Presentation Pipeline that transforms immutable Payment Engine results into immutable presentation models and UI-ready view models.

The pipeline establishes the canonical presentation layer of the Payments Capability while remaining independent of UI frameworks, payment providers, and business processing.
