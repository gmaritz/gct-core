# Objective

Implement the canonical Payment Engine.

The Payment Engine orchestrates the complete payment workflow by coordinating validation, policy evaluation, payment processing, and aggregate construction.

The engine performs orchestration only.

The engine never performs validation, policy evaluation, processing, or provider communication itself.

---

- Engine orchestration
- Immutable execution context
- Unit tests
- Barrel exports

# Engine Execution Flow

The execution order is fixed.

```text
1.

Create PaymentEngineContext

↓

2.

Execute Validation Pipeline

↓

3.

Execute Policy Pipeline

↓

4.

Execute Processing Pipeline

↓

5.

Construct Payment Aggregate

↓

6.

Create PaymentEngineResult
```

No step may be reordered.

---

# PaymentExecutionContext

The engine maintains an immutable execution context.

```text
PaymentExecutionContext

    ValidationResult

    PolicyResult

    ProcessingResult

    PaymentAggregate

    Metadata
```

This context exists only within the engine.

Processing contexts remain independent.

---

# Fail-Fast Rules

## Validation Failure

Engine returns unsuccessful result.

No policy execution.

No processing.

---

## Policy DENY

Engine returns unsuccessful result.

Processing is skipped.

---

## Policy REQUIRE_ACTION

Engine returns successful result with pending execution.

Processing is not started.

---

## Processing Failure

Engine returns unsuccessful result.

Aggregate construction is skipped.

---

# Engine Result

Returns:

```typescript
PaymentEngineResult
```

Containing:

- success
- payment aggregate
- validation result
- policy result
- processing result
- execution metadata

Immutable.

# Milestone Outcome

Upon successful completion, GCT Core shall expose a deterministic, provider-independent Payment Engine that orchestrates validation, policy evaluation, payment processing, and aggregate construction through immutable execution contexts.

The engine establishes the canonical orchestration layer of the Payments Capability while remaining independent of payment gateways, provider SDKs, and presentation concerns.
