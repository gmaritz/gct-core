# Objective

Implement the canonical Payment Processing Framework.

The framework coordinates provider-independent payment processing through immutable processing stages.

The framework performs orchestration only.

Processing stages never contain business validation, policy evaluation or gateway communication.

---

# Processing Status

Each processor returns one of:

```text
COMPLETED

SKIPPED

PENDING

FAILED
```

Definitions:

### COMPLETED

Stage completed successfully.

---

### SKIPPED

Stage intentionally bypassed.

Example:

Immediate-settlement payment methods.

---

### PENDING

Processing will continue later.

Example:

Asynchronous authorization.

---

### FAILED

Processing cannot continue.

---

# Processing Context

Each processor receives:

```typescript
PaymentProcessingContext
```

Containing immutable snapshots of:

- payment
- reservation
- pricing
- payment method
- processing metadata

Each processor returns a new immutable context.

Processors never mutate context.

---

# Processing Result

Pipeline returns:

```typescript
PaymentProcessingResult
```

Containing:

- success
- stage results
- final context
- warnings
- metadata

Immutable.

---

# Processor Registry

Responsibilities:

- register()
- unregister()
- resolve()
- resolveAll()

Rules:

- duplicate processor rejection
- deterministic ordering
- immutable collections

---

# Processing Pipeline

Responsibilities:

- resolve processors
- execute processors
- enrich context
- stop on FAILED
- return immutable result

Pipeline never invokes payment gateways.

# Milestone Outcome

Upon successful completion, GCT Core shall expose a deterministic, provider-independent Payment Processing Framework that coordinates immutable payment processing stages through stateless processors.

The framework establishes the canonical processing layer of the Payments Capability while remaining independent of payment gateways and payment provider SDKs.
