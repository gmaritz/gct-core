# Objective

Implement the canonical Payment Provider Integration layer.

The integration layer coordinates payment operations through provider-independent gateway contracts.

The Application Layer remains completely independent of payment provider SDKs.

# PaymentGateway

The gateway defines the canonical provider contract.

Supported operations:

- AUTHORIZE
- CAPTURE
- SETTLE
- REFUND
- STATUS

No provider-specific terminology shall appear in the interface.

---

# PaymentGatewayRequest

Immutable request.

Contains:

- payment reference
- reservation reference
- provider reference
- operation
- payment method
- currency
- amount
- metadata

---

# PaymentGatewayResult

Immutable result.

Contains:

- success
- provider reference
- transaction reference
- authorization status
- capture status
- settlement status
- payment status
- warnings
- metadata

The result normalizes provider responses into provider-neutral concepts, but a provider observation is not by itself an authorised canonical Payment lifecycle transition.

### Proposed D05 outcome boundary

Verification evidence, canonical Payment status and Reservation state are distinct. A verified PayFast `COMPLETE` must be preserved as evidence without advancing canonical Payment status or fabricating authorisation, capture, settlement, events, amounts or timestamps. It does not prove full Reservation settlement and must not automatically confirm a Reservation while the necessary canonical transition is unresolved.

Before any such transition, a separately approved provider-neutral contract must define transition meaning, acceptable evidence, resulting status, domain event and timestamp semantics and the PayFast mapping. Evidence representation and persistence remain unresolved. Existing contracts for cancellation, failure, refunds and other outcomes are not changed by this proposal.

---

# PaymentProviderContext

Contains immutable execution context for provider operations.

Includes:

- payment aggregate
- gateway request
- operation
- metadata

---

# PaymentProviderIntegrationService

Responsibilities:

1. Create gateway request.
2. Invoke PaymentGateway.
3. Normalize provider response.
4. Return immutable PaymentGatewayResult.

Business failures are returned as result objects.

Unexpected technical exceptions are allowed to propagate.

# Milestone Outcome

Upon successful completion, GCT Core shall expose a deterministic, provider-independent Payment Provider Integration layer that coordinates payment operations through immutable gateway contracts.

The integration layer establishes the canonical boundary between the Application Layer and Infrastructure Layer, ensuring that payment provider implementations remain replaceable without affecting application architecture.
