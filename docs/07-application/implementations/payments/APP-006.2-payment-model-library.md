# Objective

Implement the canonical Payment Model Library.

The model library defines the immutable settlement language of GCT Core and provides shared contracts for all payment-related application services.

The library shall be provider-independent and reusable across future Payment, Invoicing, Accounting and Financial Reporting capabilities.

# Model Categories

## Identity

Defines immutable payment identity.

Includes:

- PaymentReference
- TransactionReference

---

## Payment Method

Defines settlement mechanisms.

Includes:

- PaymentMethod
- PaymentInstrument
- PaymentProviderReference

Examples:

- Card
- EFT
- Instant Payment
- Wallet
- Bank Transfer

Provider-independent.

---

## Authorization

Defines authorization outcome.

Includes:

- AuthorizationRecord
- AuthorizationStatus

Contains:

- authorization id
- timestamp
- provider reference
- status

---

## Capture

Defines capture outcome.

Includes:

- CaptureRecord
- CaptureStatus

Contains:

- capture id
- amount
- timestamp
- provider reference

---

## Settlement

Defines commercial settlement.

Includes:

- SettlementRecord
- SettlementStatus
- SettlementReference

Contains:

- settlement identifier
- settled amount
- settlement date
- currency
- provider reference

---

## Refund

Defines refund information.

Includes:

- RefundRecord
- RefundStatus

Supports:

- full refund
- partial refund
- multiple refunds

---

## Lifecycle

Defines payment lifecycle.

Includes:

- PaymentStatus
- PaymentState
- PaymentTimeline
- PaymentEvent
- PaymentEventType

Canonical lifecycle:

```text
Created

↓

AuthorizationRequested

↓

Authorized

↓

CaptureRequested

↓

Captured

↓

SettlementRequested

↓

Settled

↓

Completed
```

Alternative paths:

```text
AuthorizationFailed

↓

Cancelled
```

```text
Captured

↓

RefundRequested

↓

Refunded
```

---

## Metadata

Defines immutable metadata.

Includes:

- PaymentMetadata
- PaymentAudit

Contains:

- creation timestamps
- update timestamps
- correlation identifiers
- audit references

---

# PaymentEvent

Introduce a canonical PaymentEvent model.

Represents lifecycle transitions.

Examples:

- PaymentCreated
- AuthorizationRequested
- AuthorizationApproved
- AuthorizationDeclined
- CaptureRequested
- CaptureCompleted
- SettlementCompleted
- RefundRequested
- RefundCompleted

The model is informational only.

It introduces no business behaviour.

---

# Provider Independence

No model shall reference:

- Stripe
- Adyen
- PayGate
- PayPal
- Ozow
- Peach Payments

Provider-specific identifiers shall be represented only through PaymentProviderReference.

---

# Immutability

All models expose:

- readonly properties
- readonly collections

Requirements:

- defensive copying
- cloned dates
- immutable collections

---

# Coding Standards

Follow:

- APP-000

Requirements:

- Immutable contracts
- Shared reusable models

# Aggregate Integration

Refactor Payment Aggregate to consume the canonical model library.

The aggregate shall no longer define local payment structures.

All payment contracts originate from the Payment Model Library.

Future milestones may extend the model library with:

---

# Milestone Outcome

Upon successful completion, GCT Core shall expose a provider-independent Payment Model Library that defines the canonical settlement language of the platform.

The library establishes immutable shared payment contracts for authorization, capture, settlement, refunds and payment lifecycle management while remaining independent of payment gateway implementations.
