# Objective

Implement the canonical Payment Validation Pipeline.

The pipeline validates payment requests before they enter the Payment Engine.

Validation is responsible for determining business correctness and settlement readiness.

Validation never performs payment processing.

---

# Scope

## Included

- Validation contracts
- Validation models
- Stateless validators
- Validation pipeline
- Unit tests
- Barrel exports

---

## Excluded

- Payment processing
- Provider communication
- Gateway APIs
- Payment authorization
- Payment capture
- Payment settlement

# Validation Stages

## REQUEST

Validates:

- required request
- payment identifier
- payment method
- currency
- reservation reference

---

## RESERVATION

Validates:

- reservation exists
- reservation status
- reservation payable
- reservation not cancelled

---

## PRICING

Validates:

- pricing snapshot exists
- totals present
- payable amount greater than zero
- currency consistency

---

## SETTLEMENT_READINESS

Validates:

- supported payment method
- supported currency
- amount consistency
- settlement metadata
- payment lifecycle state

---

## GATEWAY_READINESS

Provider-independent validation only.

Validates:

- gateway request completeness
- provider reference availability
- correlation identifiers
- payment context completeness

No gateway API calls occur here.

---

# Validation Result

The pipeline returns:

```typescript
PaymentValidationResult
```

Containing:

- success
- stage
- errors
- warnings
- metadata

The result is immutable.

---

# Validation Error

Each error contains:

- stage
- code
- message
- severity

All validation errors are immutable.

---

# Critical Fail-Fast

The pipeline stops immediately when a validator returns one or more critical errors.

Subsequent validators are not executed.

---

# Constructor Injection

The pipeline receives validators through constructor injection.

Example:

```typescript
new PaymentValidationPipeline(
    requestValidator,
    reservationValidator,
    pricingValidator,
    settlementReadinessValidator,
    gatewayReadinessValidator
)
```

Validators never instantiate one another.

---

# Milestone Outcome

Upon successful completion, GCT Core shall expose a deterministic, provider-independent Payment Validation Pipeline that validates payment requests through layered, immutable, stateless validators before payment processing begins.

The pipeline establishes the canonical validation foundation for all payment processing while remaining independent of payment gateways and commercial settlement execution.
