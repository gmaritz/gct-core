# Objective

Implement the canonical Reservation Presentation Pipeline.

The Presentation Pipeline transforms Reservation application results into reusable presentation models and finally into UI-specific view models.

Presentation is a transformation layer.

It performs no business orchestration.

# Presentation Architecture

The Reservation Presentation Pipeline follows APP-001E.

```text
Reservation Result

        │

        ▼

Reservation Presentation Mapper

        │

        ├───────────────┐
        ▼               ▼

Reservation        Reservation
Presentation       Lifecycle
Model              Presentation
                   Model

        └───────────────┘
                │

                ▼

Reservation ViewModel Provider

                │

                ▼

Reservation View Model
```

---

# Reservation Presentation Mapper

Create

```typescript
ReservationPresentationMapper
```

Responsibilities

- transform ReservationResult
- create ReservationPresentationModel
- create ReservationLifecyclePresentationModel
- remain UI independent

The mapper shall never

- execute business rules
- call services
- perform validation
- invoke providers

---

# Reservation Presentation Model

Represents immutable commercial reservation information.

Typical information

- reservation number
- journey summary
- traveller summary
- accommodation summary
- pricing summary
- payment summary

Remain immutable.

---

# Reservation Lifecycle Presentation Model

Represents operational booking information.

Typical information

- reservation status
- booking progress
- payment progress
- outstanding actions
- timeline summary
- next recommended action

Remain immutable.

---

# Reservation ViewModel Provider

Create

```typescript
ReservationViewModelProvider
```

Responsibilities

- transform presentation models
- compose Reservation View Model
- apply UI defaults
- remain stateless

The provider shall never execute business logic.

---

# Reservation View Model

Represents the UI-ready reservation.

Examples

- Booking Summary
- Reservation Card
- Reservation Details
- Customer Portal Reservation
- Agent Reservation View

View Models remain presentation-specific.

---

# Milestone Outcome

Upon successful completion, GCT Core shall expose a canonical Reservation Presentation Pipeline that transforms Reservation application results into reusable presentation models and UI-specific view models.

By separating commercial reservation data from operational lifecycle presentation, the pipeline enables consistent presentation across customer portals, agent consoles, mobile applications and future channels while remaining fully compliant with APP-001E.
