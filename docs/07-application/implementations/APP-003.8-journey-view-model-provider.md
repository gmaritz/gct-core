# Objective

Implement the canonical Journey presentation pipeline.

The implementation transforms Journey Composition application results into reusable presentation models and exposes presentation-specific view models through a dedicated provider.

---

- Journey View Model Provider

- Barrel exports

---

## Excluded

- HTTP
- Journey composition
- Provider integrations

# Journey Presentation Mapper

Create

```typescript
JourneyPresentationMapper
```

Responsibilities

- transform JourneyCompositionResult
- produce JourneyPresentationModel
- remain presentation-independent of any specific UI

---

# Journey Presentation Model

Create

```typescript
JourneyPresentationModel
```

Purpose

Represent the canonical presentation-ready view of a Journey.

Typical fields

- identity
- title
- subtitle
- destination
- duration
- hero image
- highlights
- accommodation summary
- experience summary
- primary price
- badges
- CTA metadata

Immutable.

---

# Journey View Model Provider

Create

```typescript
JourneyViewModelProvider
```

Responsibilities

- consume JourneyPresentationModel
- produce HomepageJourneyViewModel
- isolate UI concerns from application contracts

---

# Homepage Journey View Model

Create

```typescript
HomepageJourneyViewModel
```

Purpose

Provide only the information required by the homepage presentation.

The View Model shall not expose application models.

---

# Canonical Presentation Flow

```text
JourneyCompositionResult

        │

        ▼

JourneyPresentationMapper

        │

        ▼

JourneyPresentationModel

        │

        ▼

JourneyViewModelProvider

        │

        ▼

HomepageJourneyViewModel
```

---

# Responsibilities

The mapper shall

- transform application contracts
- normalise presentation data
- remain UI-agnostic

The provider shall

- compose homepage view models
- apply presentation defaults
- remain free of business rules

Neither component shall

- call providers
- execute application services
- evaluate policies
- perform validation

# Milestone Outcome

Upon successful completion, GCT Core shall expose a canonical Journey presentation pipeline that transforms immutable application results into reusable presentation models and presentation-specific view models.

The implementation preserves strict separation between the Application Layer and the Presentation Layer while enabling multiple user interfaces to consume a single, consistent representation of a composed Journey.
