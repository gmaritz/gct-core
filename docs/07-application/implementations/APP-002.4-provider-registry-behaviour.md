# Objective

Implement the behavioural foundation of the Accommodation Provider Registry.

The Provider Registry is responsible for registering, resolving and discovering accommodation providers.

The registry shall remain supplier independent.

No provider implementations shall be introduced.

---

# Architectural Principle

The Accommodation Engine communicates with the Provider Registry.

The Provider Registry communicates with Provider Adapters.

The Accommodation Engine shall never communicate directly with individual providers.

---

## Included

- Provider resolution
- Provider discovery
- Capability discovery scaffolding
- Registry unit tests
- Barrel updates

## Excluded

- Hotelbeds implementation

- Ranking policies
- Accommodation search orchestration

# Registry Responsibilities

The Provider Registry shall:

- Register providers.
- Unregister providers.
- Resolve providers by identifier.
- Resolve all providers.
- Discover provider capabilities.
- Prevent duplicate registrations.
- Expose immutable provider collections.

---

# Registry Contract

Expand the existing registry.

Example

```typescript
export interface ProviderRegistry {

    register(provider: AccommodationProvider): void;

    unregister(providerId: string): void;

    resolve(providerId: string): AccommodationProvider | undefined;

    resolveAll(): ReadonlyArray<AccommodationProvider>;

    supports(
        providerId: string,
        capability: string
    ): boolean;

}
```

The registry shall remain supplier independent.

---

# Behaviour

## Register

Registers a provider.

Duplicate provider identifiers shall not be permitted.

---

## Unregister

Removes a provider.

Removing an unknown provider shall not throw an exception.

---

## Resolve

Returns a provider by identifier.

Returns undefined if not found.

---

## Resolve All

Returns every registered provider.

Return type shall be immutable.

---

## Supports

Returns whether a provider advertises a capability.

Implementation shall remain placeholder until APP-002.5.

Example

```text
Hotelbeds

supports("SEARCH")

↓

true
```

# Capability Discovery

Introduce placeholder capability discovery only.

Do not implement capability models yet.

The Provider Registry prepares for:

- Search
- Details
- Availability
- Images
- Content
- Rates

Actual capability contracts belong to APP-002.5.

---

# Error Handling

The registry shall:

- Reject duplicate provider registrations.
- Return undefined for unknown providers.
- Remain deterministic.
- Avoid throwing unnecessary runtime exceptions.

# Milestone Outcome

Upon successful completion, the Accommodation Engine shall contain a fully functional Provider Registry capable of registering, resolving and managing accommodation providers independently of supplier implementations.

The Provider Registry shall establish the behavioural foundation for future Provider Capability discovery, Hotelbeds integration and multi-provider accommodation orchestration while preserving complete supplier independence.
