# Objective

Implement the structural layout of the Landing Page Hero.

This milestone establishes the reusable Hero component, page hierarchy and responsive layout without introducing final imagery or marketing content.

The objective is to create the structural foundation upon which the remaining Hero milestones will build.

---

# Scope

Included

- Hero partial
- Hero layout
- Shared container usage
- Responsive structure
- Hero CSS
- Hero JavaScript scaffold
- Landing page integration

Excluded

- Final photography
- Overlay styling
- Animation
- Final copy
- CTA styling
- Scroll indicator
- CMS integration

# Landing Page Integration

Integrate the Hero immediately beneath the Global Navigation.

```
Landing Page

Navigation

Hero

Featured Experiences (placeholder)

Remaining sections (future milestones)
```

---

# Layout

The Hero shall consume the shared Design System container.

Do not create component-specific page widths.

Required layout

```
<section class="hero">

    <div class="container">

        Hero Content

    </div>

</section>
```

The Hero background shall remain full width.

The content shall remain constrained inside the shared container.

---

# Hero Height

Desktop

```
min-height: 90vh;
```

Mobile

Allow natural height while maintaining generous spacing.

---

# Hero Content Structure

The Hero shall contain the following semantic structure.

```
<section class="hero">

    <div class="container">

        <div class="hero__content">

            H1

            Intro paragraph

            CTA group

        </div>

    </div>

</section>
```

Content values may use placeholders during this milestone.

Example

```
H1

Premium Private Experiences

Paragraph

Placeholder content.

Buttons

Explore Experiences

Plan Your Journey
```

---

# CTA Group

Create the structural container only.

```
<div class="hero__actions">

    Primary Button

    Secondary Button

</div>
```

Button styling will be refined in IMP-002.4.

---

# Container

The Hero shall consume the shared Design System container.

No Hero-specific container implementation is permitted.

---

# CSS Responsibilities

hero.css shall define only

- layout
- spacing
- flex/grid structure
- responsive layout
- section sizing

No final visual styling shall be introduced during this milestone.

---

# JavaScript Responsibilities

Create hero.js.

No behaviour is required.

The file serves as the future enhancement entry point.

---

# Accessibility

Requirements

- semantic section
- one H1
- logical heading order
- keyboard accessible buttons
- no accessibility regression

---

# Performance

No blocking JavaScript.

No inline styles.

No layout shift.

Consume DS-001 Design Tokens.

---

# Acceptance Criteria

Implementation is complete when

- Hero partial exists.
- Landing page renders Hero beneath Navigation.
- Shared container is used.
- Hero occupies approximately 90vh.
- Responsive layout is implemented.
- Hero consumes Design Tokens.
- CSS remains modular.
- JavaScript scaffold exists.
- Build succeeds.
- Tests pass.
- Startup verification passes.
