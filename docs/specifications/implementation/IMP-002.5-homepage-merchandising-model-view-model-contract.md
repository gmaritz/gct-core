# Objective

Implement the Homepage Merchandising presentation architecture.

This milestone establishes the canonical View Model Library for the frontend and formalises the presentation contracts consumed by the Homepage Showcase.

The Homepage Showcase shall render View Models only.

No business rules shall exist within the presentation layer.

---

# Architectural Principle

Presentation components render presentation contracts.

They shall never determine:

- which journeys appear
- pricing
- supplier selection
- campaign priorities
- merchandising logic
- accommodation selection

Those responsibilities belong to the Business Layer.

---

# Presentation Architecture

```
Hotelbeds

        │

Accommodation Engine

        │

        │

        │

Homepage Showcase View Model Provider

        │
```

Every layer has a single responsibility.

# View Model Design Principles

View Models represent presentation contracts.

They are independent of:

- Domain Entities
- Database Models
- Supplier Models
- API Contracts
- Business Rules

View Models may compose other reusable View Models.

Example

```
HomepageShowcaseViewModel

↓

JourneyCardViewModel

↓

PriceViewModel

↓

ImageViewModel

↓

CTAViewModel
```

Presentation Components consume View Models.

View Models consume Business Objects supplied by the View Model Provider.

This separation ensures presentation remains stable while business implementations evolve.

# Homepage Showcase View Model Provider

The Homepage Showcase View Model Provider transforms Business Objects into Presentation Contracts.

Responsibilities

- Build HomepageShowcaseViewModel
- Build JourneyCardViewModels
- Build EditorialPanelViewModel
- Build shared presentation primitives
- Supply placeholder data during early implementation

The Provider shall never:

- query Hotelbeds directly
- perform merchandising
- calculate pricing
- rank journeys
- select featured journeys

Those responsibilities belong to dedicated Business Services.

---

# Controller Responsibilities

The Frontend Controller shall:

- Request HomepageShowcaseViewModel
- Pass the View Model directly to the Homepage Showcase
- Contain no presentation transformation logic
- Contain no merchandising logic

# Milestone Outcome

Upon successful completion, GCT Core shall expose a canonical View Model Library that forms the presentation contract between the Business Layer and the Component Library.

The Homepage Showcase shall become completely independent of supplier integrations, merchandising implementation, pricing logic and future accommodation providers.

This milestone establishes the presentation architecture that will support Hotelbeds integration, the Homepage Merchandising Service, Accommodation Gallery, Journey Rotation, Personalisation and future campaign management without requiring structural changes to the frontend.
