## 2. Objective

Resolve the mismatch between the local Hotelbeds TLS configuration, which supplies certificate/key file paths, and the shared Hotelbeds integration loader, which expects PEM contents.

Enable the commercial application to use the existing file-based TLS configuration without changing the shared PEM-only configuration contract.

This is a focused configuration correction, not an implementation of the Cape Winelands commercial flow.

## 3. Required Architecture

Follow the existing approved architecture and `docs/09-governance/GOV-DEV-001-DEVELOPMENT-PROCESS.md`.

1. Keep `hotelbeds-integration-config.ts` PEM-only.
2. Preserve the existing R8 certification-verification path-loading behaviour.
3. Add an explicit file adapter at the appropriate application configuration/composition boundary for the commercial Hotelbeds runtime.
4. Resolve relative file paths deterministically from the project root; support absolute paths.
5. Read only explicitly configured certificate, private-key and optional CA files.
6. Pass the resulting PEM contents to the existing shared configuration loader.
7. Preserve existing private-key passphrase handling.
8. Apply the adapter wherever the commercial application composes the shared Hotelbeds provider, not just to the Cape Winelands journey.
9. Do not introduce implicit path detection into the shared PEM-only loader.
10. Do not create a second Hotelbeds transport, configuration loader or provider.

Use the existing configuration conventions and repository structure. Keep the change as small as possible.

## 4. Security Requirements

- Never log certificate contents, private-key contents, passphrases or authentication credentials.
- Do not include secret values or file contents in thrown error messages.
- Configuration errors may identify the relevant variable name, but must not disclose its value.
- Restrict file reads to explicitly configured TLS files.
- Preserve existing TLS validation and transport behaviour.
- Do not modify credentials or secret values.
- Do not make live Hotelbeds requests.

If diagnostics indicate that a TLS passphrase may have been exposed in retained or shared output, report that separately without reproducing it.

## 5. Tests

Add or update focused tests covering:

- Relative file paths.
- Absolute file paths.
- Missing and unreadable certificate/key files.
- Optional CA configuration.
- Correct PEM contents passed to the shared loader.
- Private-key passphrase handling.
- Safe errors that do not reveal configuration values or file contents.
- Existing R8 certification-verification behaviour remains unchanged.

Use temporary test fixtures or mocks. Do not expose real certificate or key material in test output.

## 6. Scope Restrictions

Do not implement or modify:

- Cape Winelands journey dates or itinerary;
- Hotelbeds property mappings;
- commercial Availability requests;
- room allocation;
- APP-005 pricing;
- Reservation or booking behaviour;
- payment;
- unrelated application configuration;
- database schemas or migrations.

Do not change the shared PEM-only loader contract.
